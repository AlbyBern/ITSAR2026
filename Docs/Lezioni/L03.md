# Lezione 03 – Prompt engineering e Input System

## Punto di partenza (`lezione-03-inizio`)

- **`CLAUDE.md`** nella radice della repository: il *file di contesto* del progetto.
  Descrive versione di Unity, pacchetti, convenzioni e struttura. Allegalo (o fallo leggere)
  all'AI all'inizio di ogni conversazione: è la prima parte di ogni buon prompt.
- **`Input/GameControls.inputactions`**: asset dell'Input System con l'Action Map `Player`
  (`Move`, `Sprint`, `PlaceTower`, `Pause`). L'opzione *Generate C# Class* è attiva:
  Unity genera la classe `GameControls` da usare nel codice.
- Il **Player** in scena: CharacterController sulla radice, grafica nei figli
  (`Body` e `Visor`, che indica la direzione).
- Canvas `UI` con il pannello di pausa (disattivato) ed `EventSystem` con
  `InputSystemUIInputModule`.

## Laboratorio

Obiettivo: ottenere il movimento del player e la pausa scrivendo prompt precisi.

1. Leggi `CLAUDE.md` e apri `GameControls.inputactions`: quali Action esistono? Di che tipo?
2. Scrivi il prompt per il `PlayerController` usando la struttura:
   **contesto → obiettivo → vincoli → struttura → criteri di accettazione**.
3. Verifica che il codice usi **solo** l'Input System (niente `Input.GetAxis`).
4. Aggiungi il componente al Player e testa: movimento, rotazione, sprint.
5. Secondo prompt: una `CameraFollow` dall'alto con inseguimento morbido.
6. Terzo prompt: il `PauseMenu` (Esc / Start), collegando il bottone *Riprendi*.
7. Commit dopo ogni sistema funzionante.

### Prompt di esempio

> [allega CLAUDE.md] Unity 6, URP, Input System. Ho un asset GameControls (classe C# generata)
> con Action Map Player: Move (Vector2), Sprint (Button). Scrivi un PlayerController per una
> visuale dall'alto: CharacterController sulla radice, movimento relativo all'orientamento della
> camera, gravità applicata a mano, sprint con moltiplicatore, rotazione morbida verso la
> direzione di movimento. Parametri in Inspector con [SerializeField]. Abilita le action in
> OnEnable e disabilitale in OnDisable. Non usare Input.GetAxis.

### Criteri di accettazione

- Premendo "su" il player va verso l'alto dello schermo, qualunque sia la rotazione del player
- Velocità uguale a 30 e a 300 FPS
- In pausa il player non si muove e il bottone *Riprendi* funziona
- Nessun errore in Console: con il solo Input System attivo, il vecchio `Input.GetAxis` va in errore
